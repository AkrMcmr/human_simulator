# ゲーム企画書: 「はじまりのふたり」（仮題）

状態: **企画案（未承認・未実装）**。作成 2026-09-30。モデルの既定・研究の優先順位（[STATUS](../STATUS.md)、[中期目標](../MIDTERM_GOALS.md)）は変えない。

## 1. ひとことで

**言葉も約束事も持たない二人を、命令せずに「世界の置き方」だけで見守り、次に何をするかを読み当てるゲーム。**

プレイヤーは神でも操作者でもなく「世界の管理人」。二人に直接指示はできない。できるのは、食料や焚き火（暖かい場所）の置き方を変えることと、二人の見ているものを覗いて次の行動を予想すること。二人は本リポジトリの人間モデル（既定 human 0.2.0）でそのまま動き、筋書きはない。

- ジャンル: 観察・予想パズル＋箱庭
- 形式: 既存の観察UI（`app/`、`npm run dev`）の上に追加する一人用のローカルゲーム。サーバー・DB・LLMは使わない
- プレイ時間: 1ステージ 3〜8分（600ステップ程度を早送りと一時停止で）

## 2. なぜこのモデルでゲームにするのか

多くのゲームの住人は台本や、裏で全部を知っているAIで動く。このモデルの二人は違う。

| モデルの性質（実装済み） | ゲームでの手触り |
| --- | --- |
| 本人には16u以内の視界・20u以内の雑音まじりの音しか渡らない（`senseWorld`） | 「本人の目」視点に切り替えると、プレイヤーが知っていることを本人は知らない、と分かる。予想の難しさの源 |
| 相手ごとに危害の証拠を記憶し、忘却で薄れる（Beta 証拠） | 一度ぶつかって痛い思いをすると距離を取る。時間と近接で警戒がほどける（history-v1 P2 で確認済み） |
| 行動ごとの距離変化を学習し、効用に反映（0.2.0 `predictedSafety`） | 資源を共有させると、二人は衝突だけを避けるようになる（world-v1 で確認済み） |
| 判断ごとに全候補の効用の内訳を記録（`DecisionTrace.scores[].terms`） | 予想の「答え合わせ」で、なぜその行動を選んだかを項目別に見せられる |
| 同じシード・同じ介入なら完全に再現（keyed RNG） | 自分のプレイを再生・共有でき、「同じ条件で別の置き方ならどうなったか」を比べられる |

つまり、**見た目の演出ではなく、中身の計算そのものを読み解くことが遊びになる**。これはモデルの説明ツールとしても役に立つ。

## 3. ゲームの約束（モデルのルールを壊さないための原則）

[AGENTS.md](../../AGENTS.md) と [設計と情報の境界](../development/ARCHITECTURE.md) に合わせる。

1. **二人を操作しない。** プレイヤーの介入は「実験者の層」で世界（資源の位置・量）を変えることに限る。二人はそれを通常の知覚として受け取る。二人の記憶や判断を直接書き換える操作は、別枠の「実験室モード」（6章）でのみ扱い、記録に明示する。
2. **内面はプレイヤーにだけ見える。** 効用の内訳や危害推定の表示は観察用で、判断には戻さない。表示が乱数を消費したりエンジン状態を変えたりしない。
3. **意味を埋め込まない。** 「仲良し」「敵」「合図が通じた」といったラベルを二人に与えない。画面の言葉も「接触痛の少なさ」「近くにいた時間」など測れる量で書く。
4. **人間らしさを主張しない。** 画面に「これは未校正の探索モデルで、本物の人間の信頼や恐怖の再現ではない」と常に示す。ゲームで面白い出来事が起きても、モデルが人間に近い証拠にはしない。
5. **実行中にLLM・外部API・時刻・`Math.random` を使わない。** 演出用の揺らぎも、表示専用のシード付き乱数で作り、エンジンの乱数とは分ける。
6. **CLIとUIで同じエンジン。** ゲームの一回のプレイは「設定＋シード＋介入ログ」で完全に決まり、CLIで同じ結果を再生できる。

## 4. コアループ

```
 ① 状況を見る（全体図 / 本人の目）
        ↓
 ② 予想する：「Aは次の20ステップで何をする？」（8種類の行動から選ぶ）
        ↓
 ③ 介入する（任意・コスト制）：食料や焚き火を置く / 動かす / 減らす
        ↓
 ④ 進める（早送り。重要な出来事で自動一時停止）
        ↓
 ⑤ 答え合わせ：実際の行動と、効用の内訳「なぜそれを選んだか」
        ↓
   ①へ。ステージ終了時に目標の達成度を採点
```

## 5. モード

### A. 予想モード「ふたりの目」（最初に作る）

- 画面は二分割。左は全体図、右は選んだ一人の「本人の目」（`Observation` をそのまま描画：見えている相手の相対位置、資源の手がかり、聞こえた音）。
- 決まった時点で「次の行動は？」を選ぶ。当たると得点。自信度（3段階）を賭けられ、外れると減点。
- 答え合わせで `DecisionTrace` の効用内訳（空腹、寒さ、警戒、好奇心、予測安全など）を棒グラフで表示。「警戒が強くて離隔を選んだ」ことが見える。
- 探索選択（既定8%の均等ランダム）は「気まぐれ」と表示し、得点計算から除くか半分にする（運で負けた感じを減らす）。
- 遊びの芯: 慣れると「空腹が0.6を超えたら相手がいても食べに行く」といった規則が読めるようになる。これはモデルの理解そのもの。

### B. 箱庭モード「世界の置き方」

- 各ステージに目標と、介入に使える「手間ポイント」がある。
- 介入の種類（初版）: 食料を置く／動かす／減らす、焚き火を置く／動かす、寒さを調整する（季節）。
- 二人は自分の判断で動く。プレイヤーは置き方で「状況」を作るだけ。
- 採点は既存の指標（`packages/experiments` の `measure`、world-v1・history-v1 の指標）を使う。

### C. 実験室モード「記憶の手紙」（後期・任意）

- history-v1 の記憶介入（保持・消去・入れ替え）をプレイヤーが使える「禁じ手」として出す。使うとリプレイに「記憶介入あり」と刻まれ、通常のランキングとは別枠になる。
- 研究で何を操作しているかを体験で理解する教材の位置づけ。

## 6. ステージ案（検証済みの現象に対応づける）

各ステージは、リポジトリで**すでに複数シードで確認した挙動**を土台にする。未確認の挙動を目標にしない。

| # | 名前 | 状況 | 目標（測れる量） | 土台の証拠 |
| --- | --- | --- | --- | --- |
| 1 | ひとりの冬 | 一人だけ。食料と焚き火が遠い | 300ステップ、健康0.8以上を保つ | 身体の更新則（[MODEL](../MODEL.md)） |
| 2 | ふたつの食卓 | 二人、食料が別々 | 二人の最低健康を高く、接触痛ゼロ | world-v1 の分離配置 |
| 3 | ひとつの泉 | 食料が一か所だけ | 接触痛の起きるステップ割合を0.02未満に | world-v1（共有配置で0.04〜0.05→0.01〜0.02） |
| 4 | 痛みのあと | 開始時点で「AはBに痛い目にあった」履歴がある | Aの危険度を一定以下まで下げる | history-v1 P2（近接が続くと約0.26〜0.28低下、分離では下がらない） |
| 5 | 避けられる距離 | 4と同じ履歴、食料が別々 | 4と同じ目標。置き方を工夫しないと達成が難しい | history-v1 P2（分離では8シード中5で近づかない） |
| 6 | 声の届く夜（予定） | 暗くて視界が狭い、音だけが頼り | 未定 | **M3（最小合図）の研究結果が出るまで作らない** |

ステージ4・5が見せ場。「痛い思いをした相手に、食料の置き方で少しずつ近くにいる時間を作る」は、遊んでいて気持ちよく、しかもモデルで確認された挙動そのもの。ただし画面では「信頼を取り戻した」ではなく「危険度の推定が下がった」と書く。

シードは研究用の観察済みシード（2001–2008、3001–3008、4001–4008、5001–5008、6001–6008、6101–6104、7001–7008）とは別の範囲（例: 90000番台）を使い、ゲームのプレイ結果を研究の証拠と混ぜない。

## 7. 採点

- **予想点**: 的中×自信度。探索選択の回は除外または半分。
- **世界点**: ステージ目標の達成度＋副作用（最低健康、身体要求の負担）＋使わなかった手間ポイント。
- **読み解きボーナス**: 答え合わせで最大の効用項目を当てると加点（例: 「寒さ」）。
- ランキングはローカル保存のみ（`localStorage`は画面の利便機能としてだけ使い、エンジン状態は保存記録に置く）。

## 8. 画面構成

```
┌──────────────────────────────┬──────────────────────┐
│ 全体図（世界・資源・二人）   │ 本人の目（A / B 切替）│
│  ・介入パレット（手間 12pt） │  ・見えている相手      │
│                              │  ・資源の手がかり      │
│                              │  ・聞こえた音          │
├──────────────────────────────┴──────────────────────┤
│ 予想カード: [観察][接近][離隔][探索][摂食][保温][休息][発声] 自信 ○○○ │
├────────────────────────────────────────────────────┤
│ 時間軸（既存スライダー）／出来事マーカー（接触痛・摂食・発声）       │
│ 答え合わせ: 効用の内訳グラフ・危害推定・行動別の距離予測            │
└────────────────────────────────────────────────────┘
  常時表示: 「未校正の探索モデル。人間の再現ではありません」
```

既存の「経験から判断へ」表示（`app/decision-history.tsx`）と観察変換（`packages/observer`）を再利用する。

## 9. 技術設計の方針

| 項目 | 方針 |
| --- | --- |
| 置き場所 | 新しい `packages/game`（実験者の層）。human と world は変更しない。画面は `app/` にゲーム用のページを追加 |
| 介入 | `GameIntervention = { tick, kind: "placeResource" \| "moveResource" \| "setAmount" \| "setAmbientCold", ... }`。ステップの**間**に `WorldState` のコピーへ適用する。`stepSimulation` の「全員が同じ前の世界を知覚→同時適用」の順序は変えない |
| 再現 | 1プレイ＝`ExperimentConfig`＋シード＋介入ログ。`restoreRun` と同じ方式で最初から再計算して復元。記録には game の版、モデルID・版、RNG版を残す |
| CLI | `npm run game:replay -- --file play.json` で同じエンジンからフレームと採点を再生成できるようにする |
| 予想の答え | `DecisionTrace.selected` と `scores` を使う。表示専用で、エンジンへは戻さない |
| 版 | game 0.1.0 から開始。介入の意味・採点式を変えたら版を上げ、古い記録は拒否する（simulation と同じ「無言の移行はしない」方針） |
| テスト | 介入なしのプレイが通常の `runExperiment` と一致すること、同じ介入ログで同じ結果になること、表示処理が乱数を消費しないことを `tests/game/` で確認。モデル側は `npm run test:model` で回帰なしを確認 |

確認が必要な点: 資源の途中追加・移動はいまの `createWorld` の外で `WorldState.resources` を書き換える形になる。world の不変条件（資源の再生、配分）を壊さない書き方か、world に小さな公開関数を足すかを実装前に決める。後者なら world の版を上げる。

## 11. リスクと対策

| リスク | 対策 |
| --- | --- |
| 地味・遅い（抽象的な二人が歩くだけ） | 早送り＋出来事での自動一時停止、予想という「賭け」で緊張を作る。動きの演出は増やしても、モデルの挙動は変えない |
| 「AIが仲良くなった」と誤解される | 3章の原則4。画面の言葉を測れる量に限定し、常時注記を出す |
| ゲームのために係数を調整したくなる | ゲームの難易度は置き方・ステージ設計・シードで調整し、モデルの係数は触らない。モデルの変更は通常の研究手順（事前登録・版上げ・複数シード比較）でのみ行う |
| 研究シードとゲーム結果が混ざる | ゲーム専用のシード範囲を使い、プレイ記録は Git に含めない |
| 運の要素が強すぎる | 探索選択を点数から除く。ステージは複数シードで事前に達成率を測って選ぶ |

## 12. 所有者に決めてもらうこと

1. 優先するのは「モデルを理解する教材」寄りか、「遊んで面白い作品」寄りか（採点と画面の言葉づかいが変わる）。
2. MVPを予想モードから始めてよいか（箱庭モードの方が世界への介入の設計が要る）。
3. 実験室モード（記憶介入）をゲームに含めるか。
4. 公開画面へ載せるか。載せる場合も、研究の公開とは別の判断として扱う。
