# ADR 0002: 身体モデルをモノレポ内の別トラックとして始める

状態: 提案 / 2026-10-10（依頼者の確認待ち）

## 背景

依頼者から「いろいろな操作が可能な、限りなく現実の肉体に近い人間の3Dモデルを、ゲーム・シミュレーションで使える公開製品として作りたい。設計文書から作ってほしい」という要件が出た。

既存の Human World Lab は知覚・判断・学習の認知モデルで、身体は `Body = { hunger, fatigue, cold, health }` の抽象 4 変数、空間は 2 次元、単位は抽象である。新しい要件は 3 次元の骨格・多体動力学・生理・損傷・形式変換・エンジン連携を含み、既存の human / world / simulation の責務と大きく異なる。

## 決定

1. 身体モデルを **body track** として、既存パッケージと独立した契約（`body-contracts`）を持つ別トラックで始める。設計文書は `docs/body/` に置く。
2. 当面は同じモノレポ（`packages/body-*`）で開発する。理由は、親リポジトリの開発契約（決定論、キー付き乱数、版と記録、根拠区分、テストの流儀）をそのまま使えること、将来の橋渡し（`body-bridge-hwl`）を同じコミットで検証できること。
3. 既存の `human` / `world` / `simulation` と `body-*` は相互に import しない。接続は `body-bridge-hwl` のみで、親リポジトリの既定モデルの挙動と版は変えない。
4. 公開時（B5）に別リポジトリへ切り出す。切り出しの条件は ADR 0001 の分割条件（他プロジェクトから利用される、入出力が安定する、公開範囲やリリース周期が異なる）と同じ。
5. 忠実度の主張は [VALIDATION](../body/VALIDATION.md) のラベル（U/E/R/M）に従い、実測比較済み以外を「現実準拠」と宣伝しない。

## 検討した代替案

| 案 | 内容 | 採らない理由 |
| --- | --- | --- |
| A. 既存の `Body` 型を拡張する | contracts の `Body` に骨格・生理を足し、human / world を 3D 化する | 既定モデル human 0.2.0 の全記録・基準・研究判断が無効になる。認知と身体の責務が混ざり、親リポジトリの研究ループが止まる |
| B. 最初から別リポジトリ | 新規リポジトリで独立に開発する | 開発契約・テスト基盤・乱数・記録形式を再構築する手間が先に立つ。橋渡しの検証が二重管理になる。公開時に切り出せば十分 |
| C. 既存の人体モデル製品（統計的体型モデルや商用キャラクター生成）の上に薄い層を作る | 既製品の API を包む | 商用再配布に制約があるものが多く、公開製品の前提（BR-02）と合わない。忠実度の根拠を自分で示せない |
| D. 本トラック（採用） | 独立契約・同一モノレポ・後で切り出し | 上記の問題を避け、既存の原則を再利用できる |

## 影響

- `packages/`、`cli/`、`tests/`、`research/` に `body` 接頭辞または `body/` サブディレクトリが増える。既存のコマンド（`test:model` など）は変わらない。
- `docs/STATUS.md` と `docs/ROADMAP.md` に body track の節と参照を追加する。既存の M1〜M4 の優先順位は変えない。body track の稼働量は別に見積もる。
- 身体資産と参照データのライセンス管理が新しい作業として加わる（[PRODUCT](../body/PRODUCT.md)）。
- 親リポジトリ全体のライセンス未決定が、body track の公開の前提条件になる。
