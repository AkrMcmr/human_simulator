# 版・再現・採用

## 三種類の変更

| 変更 | 記録する版と証拠 |
| --- | --- |
| 人間の挙動・学習の変更 | humanの版。実験候補は既定と別の名前/版。旧版との差と副作用 |
| 世界・知覚契約・更新順・乱数 | world/contracts/simulation/RNGの該当版。比較する両モデルを同じ環境で再評価 |
| 評価方法・課題・閾値 | evaluator/protocolの版とハッシュ。旧版を新評価器で測り直す |

既定の3引数APIの結果を変えずに候補用の入口を追加しただけなら、既定humanの版は維持できます。ただし、基準測定値が一致することと、候補の版が区別されることを確認します。デフォルトの挙動を変えて同じ版を名乗ることは禁止です。

パッケージのpackage.jsonとモデル定数が別の意味を持つ場合は説明を残します。今のhumanパッケージ0.2.0は既定モデル（`decideHuman`、予測効用あり）を指し、旧0.1.0は`decideLegacyHuman`として同じパッケージに残っています。実行時にどちらを使うかは`packages/simulation/src/models.ts`の登録簿のidで決まります。候補時代のid`predictive-0.2.0-experimental.1`は0.2.0と同じ計算を指し、保存済み研究の再現のために残します。対照`predictive-ablated-0.2.0-experimental.1`の版は`0.2.0-experimental.1+ablated`です。既定化の手順（2026-09-10に実施）: `decideHuman`の既定を変えてhumanの版を上げ、旧版を`human-0.1.0`として登録簿に残し、core-v1基準を新版で再記録して旧基準との差を確認する。

## 記録の形式

- `human-world-lab/run`: 初期条件・チェックポイント・各ステップ。simulation 0.2.0からは`config.model`、`checkpoint.model`、`manifest.model`に選択した人間モデルのidを、`manifest.versions.human`にその版を記録する。`restoreRun`は同じモデル・版で再実行して完全一致を検証し、0.1.0形式や版・モデルの不一致は拒否する。
- `human-world-lab/evaluation`: core-v1のシード別測定と集計。比較の前に形式・集計・評価器/環境ハッシュを検証する。
- `human-world-lab/policy-study`: 政策候補の制御実験、旧版/候補/寄与無効の結果、core-v1の副作用。
- `human-world-lab/world-study`: 通常worldの条件×シード対の三版比較（world-v1）、条件別集計、寄与無効の一致、core-v1の副作用。

これらを混同しないでください。互換でない状態を読み込む場合は、旧版を使うか、明示的な移行仕様と検証を別途作ります。現状は無言の移行をしません。

## 採用の段階

1. **登録**: 仮説・反証条件・計算方法を固定。
2. **候補**: 別入口から呼び出せる実装。既定には接続しない。
3. **制御課題での支持**: 事前条件を満たしたことを記録する。実環境や人間への妥当性とは別。
4. **既定化の判断**: 通常worldでの複数条件、生活技能への副作用、互換性を確認し、ADR/研究台帳に判断を書く。予測政策候補は[0004](../../research/decisions/0004-normal-world-m1.md)の証拠をもとに所有者の指示でhuman 0.2.0として既定化した。
5. **公開**: GitHubの版とSitesの稼働版をSTATUSに区別して記載する。

既定化や公開が当該ユーザーの依頼で許可されている場合、不要な確認を追加しません。指標が合格しただけで、未依頼の公開や人間の高精度再現の主張を行いません。

## 初期の履歴について

このリポジトリはSitesの作業用GitからGitHubへ内容を同期して始まったため、初期レポートのソースコミットにはGitHubから直接checkoutできないIDがあります。GitHubへの反映コミットとその報告内のmodel/evaluator/environment hashで対応を確認します。

新しい共同開発では、原則GitHubの同じブランチ履歴を共有します。直接Gitが使える環境ではfetch/rebase/mergeで履歴を保ちます。コネクターがファイル内容の同期だけを提供する場合は、親コミットとツリー一致を確認し、履歴が同一だと装わないでください。強制pushで他者の変更を消さず、途中でmainが進んだら変更を読み直して統合します。
