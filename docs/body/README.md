# 身体モデル（body track）設計文書

状態: **設計のみ**（2026-10-10 起草）。実装、3D資産、実測データとの比較はまだありません。この文書群は、何を作るか・何を作らないか・何をもって「現実に近い」と言うかを、実装の前に固定するためのものです。

## 目的

現実の肉体に限りなく近い振る舞いをし、外部から多様な操作ができる人間の3Dモデルを、さまざまなゲーム・シミュレーションから利用できる**公開可能な製品**として設計する。

「現実に近い」は見た目の印象ではなく、形態・運動・生理・応答の4軸について、公開された計測値との一致で定義する（[CONCEPT](CONCEPT.md)）。見た目がもっともらしいアニメーションは、忠実度の証拠として扱わない。この規則は、親リポジトリの[開発契約](../../AGENTS.md)と同じ精神である。

## 既存のHuman World Labとの関係

親リポジトリの既定モデル human 0.2.0 は、知覚・判断・学習を扱う**認知モデル**で、身体は `Body = { hunger, fatigue, cold, health }` の4変数（[contracts](../../packages/contracts/src/index.ts)）に抽象化されている。位置は2次元、時間と距離は抽象単位である。

body trackは、この抽象身体を置き換えるものではなく、**別の層**として設計する。

- body trackは独自の契約（`body-contracts`）を持ち、既存の `packages/human` と `packages/world` を import しない。既存のhuman/worldもbody trackを import しない。
- 二つを接続する場合は、明示的な橋渡し（[ARCHITECTURE の「既存モデルとの橋渡し」](ARCHITECTURE.md#既存モデルとの橋渡し)）を別パッケージとして作り、どの量をどの量へ写すかを記録する。接続は将来の任意項目で、B1〜B3 の必須条件ではない。
- 実行時にLLM・外部API・壁時計・`Math.random` を使わない、観察・表示は状態を変更しない、記録に版と由来を残す、という親リポジトリの原則は body track にも適用する。

## 用語

| 用語 | 意味 |
| --- | --- |
| 身体仕様（BodySpec） | 一人の身体を生成するための入力。性別・年齢・身長・体重・体節比率・体組成など。乱数シードを含めてよい |
| 骨格（Skeleton） | 関節階層とボーン長。表示用のリグと計算用の多体系の両方の基になる |
| 可動域（ROM） | 各関節自由度の角度の上下限。年齢・性別・損傷で変化する |
| 忠実度レベル（L0〜L4） | 形態・運動・生理・応答の各軸で、どこまで現実に対応するかの段階。[CONCEPT](CONCEPT.md#忠実度レベル) 参照 |
| コマンド / 問い合わせ / イベント | 外部から身体へ与える操作、状態の読み取り、身体から外部へ通知する出来事。[OPERATIONS](OPERATIONS.md) 参照 |
| 根拠区分 | 仕様や係数の由来。ユーザー要件 / 工学的仮定 / 文献由来 / 実測比較済み の4区分。[VALIDATION](VALIDATION.md#主張ラベル) 参照 |

## この設計が守る前提

1. 仕様の各項目に根拠区分を付け、実測比較済みでないものを「現実に近い」と宣伝しない。
2. 製品に含める第三者データ・資産・ライブラリは、商用利用と再配布が許されるものに限る（[PRODUCT](PRODUCT.md#第三者資産とデータの利用可否)）。
3. 実在人物の再現、生体認証への利用、本人の同意のないスキャンの取り込みを製品の用途として支援しない。
4. 設計を変更するときは、この文書群を更新し、挙動が変わる場合は版を上げる。
