# 形式・単位・座標系・互換性

## 単位

| 量 | 内部単位 | 備考 |
| --- | --- | --- |
| 長さ | メートル（m） | Unreal へは cm に変換 |
| 質量 | キログラム（kg） | |
| 時間 | 秒（s） | 刻みは固定 `dt` |
| 角度 | ラジアン | 文書・表示では度を併記してよい |
| 力・トルク | N、N·m | |
| エネルギー・仕事率 | J、W | 代謝は W、累積は J |
| 温度 | ℃（差分は K） | |

すべての数値フィールドは単位をスキーマで固定し、ファイルには単位名を含めない（二重定義を避ける）。例外として可読性のため `canonical` 形式のヘッダに `units: "SI"` を一つ書く。

## 座標系

正準座標系は **glTF 2.0 と同じ右手系・Y上・前方 +Z**（キャラクターの正面が +Z を向く）。アダプタで次のように変換する。

| 環境 | 手系 | 上 | 前 | 長さ | 変換 |
| --- | --- | --- | --- | --- | --- |
| glTF / three.js / VRM | 右手 | +Y | +Z（VRM 1.0 は +Z 前） | m | なし |
| Unity | 左手 | +Y | +Z | m | X を反転（または Z 反転。アダプタで一方に固定） |
| Unreal | 左手 | +Z | +X | cm | 軸入れ替え + 反転 + ×100 |
| Godot | 右手 | +Y | −Z | m | Z を反転 |
| Blender | 右手 | +Z | −Y | m | 軸入れ替え |

回転は内部では単位四元数で保持し、関節角度はその関節の局所フレームでのオイラー角（順序を関節ごとに定義）として API に出す。回転順序の違いによる取り違えを防ぐため、`query.pose` は四元数と角度の両方を返す。

基準姿勢は **A ポーズ**（腕を体側から約 45 度下ろした姿勢）を正準とし、T ポーズへの変換を用意する。VRM 1.0 の T ポーズ要件と Unity Humanoid の要求を満たすため、書き出し時に T ポーズのバインドポーズも生成する。

## ボーン命名

Rig-Core の正準名は **VRM 1.0 のヒューマノイドボーン名**（`hips`, `spine`, `chest`, `upperChest`, `neck`, `head`, `leftUpperArm`, `leftLowerArm`, `leftHand`, `leftUpperLeg`, `leftLowerLeg`, `leftFoot`, `leftToes`, 右側同様、`leftEye`, `rightEye`, `jaw`、指はVRM の `leftThumbMetacarpal` 等）に合わせる。理由は、VRM 1.0 が人型の必須・任意ボーンを明確に定義しており、Unity Humanoid との対応表が公開されているため。

Rig-Full の追加ボーン（脊椎の集約節、肩甲骨、鎖骨の分離、足趾の分割など）は `body.` 接頭辞付きの独自名とし、Rig-Core への射影表を持つ。

| 対応先 | 方法 |
| --- | --- |
| Unity Humanoid | VRM 名からの公式対応に従う |
| Mixamo | 対応表 `mixamo.json` |
| Unreal Mannequin（UE4/UE5） | 対応表 `ue-mannequin.json`。名前のみの対応で、MetaHuman の資産は含まない |
| Godot SkeletonProfileHumanoid | 対応表 `godot-humanoid.json` |
| BVH（一般的な CMU/Mixamo 系） | 対応表 + リターゲット設定 |

## 顔の形状名

正準は FACS の AU 番号（`AU01`, `AU02`, ... 強度 0〜1）。ARKit 52 の形状名（`browInnerUp`, `jawOpen`, ... ）との双方向変換表を `body-face` に持ち、glTF / VRM 書き出し時には ARKit 名のモーフターゲットを生成する。VRM 1.0 の表情プリセット（`happy`, `angry`, `sad`, `relaxed`, `surprised`, 視線、口形）へは AU の組み合わせで写す。

## 正準形式

MIME 的な識別子と版を先頭に持つ JSON。大きい配列（頂点、フレーム）は同名の `.bin` へ分離できる（glTF と同じ考え方）。

| 識別子 | 内容 | 主な項目 |
| --- | --- | --- |
| `human-body/spec` | 身体仕様 | `BodySpec`、参照する解剖データ版、シード |
| `human-body/skeleton` | 生成された骨格 | 階層、ボーン長、関節種別・自由度、可動域（調整後）、体節慣性 |
| `human-body/pose` | 一時点の姿勢 | 関節角度（局所）、ルート変換、AU、視線 |
| `human-body/motion` | 姿勢の時系列 | `pose` の配列、刻み幅、接地情報 |
| `human-body/run` | 実行記録 | 設定、全コマンド・イベント、チェックポイント、manifest（全版・資産ハッシュ・後端・環境） |
| `human-body/surface` | 体表資産 | メッシュ、スキンウェイト、ブレンドシェイプ、LOD、ソケット、資産ライセンス |

`run` は親リポジトリの `human-world-lab/run` と同じ思想（設定・版・チェックポイント・全ステップ）で、再実行してチェックポイントのハッシュ一致を検証する。別の版・後端の記録を無言で変換しない。

## 書き出し

| 形式 | 用途 | 含むもの | 備考 |
| --- | --- | --- | --- |
| glTF 2.0（`.glb`） | 一般的な配布・three.js・Godot・Blender | メッシュ、スキン、モーフターゲット、材質、アニメーション（`motion`） | 第一の配布形式。必要なら独自拡張 `EXT_human_body_*` に骨格の可動域・慣性を埋め込む（拡張名は Khronos の命名規則に従い、未登録の間はベンダ接頭辞を使う） |
| VRM 1.0 | VRM 対応アプリ | glTF + ヒューマノイド、表情プリセット、視線、スプリングボーン | 利用条件メタデータを身体資産のライセンスと一致させる |
| USD / USDZ | DCC・Omniverse・iOS | メッシュ、スケルトン（UsdSkel）、ブレンドシェイプ | 書き出しライブラリの選定は B5 |
| FBX | Unity / Unreal / Maya | メッシュ、スキン、アニメーション | 公式 SDK のライセンス制約があるため、Blender 経由の変換または glTF からの変換を既定にする |
| BVH | モーションの交換 | 骨格階層と関節角の時系列 | 回転順序と単位を明記 |
| Unity Prefab / Unreal Asset | エンジン内で直接使う | アダプタが生成 | コアの状態を含まず、`spec` への参照で再生成できるようにする |

書き出した資産には、`spec` のハッシュ、解剖データの版、体表資産のライセンス表示を埋め込む。

## 読み込みと安全性

- 外部ファイル（他者が作った `spec`・`run`・glTF）はスキーマ検証を通してから読み、頂点数・ボーン数・フレーム数・ファイルサイズに上限を設ける（NFR-06）。
- 実行可能なスクリプトや URL 参照の自動取得は、どの形式でも行わない。
- 版の不一致は拒否し、変換ツールを別に提供する。

## 互換性の約束

- 正準形式の `spec` と `pose` は、副版の間で前方互換（新しい読み手は古いファイルを読める）を保つ。
- `run` は同じ主版・同じ後端でのみ再現を保証する。
- ボーン名・AU 名の変更は主版の変更とする。
