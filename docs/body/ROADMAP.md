# ロードマップ

段階は B0〜B6。日程は約束しない。各段階は**完了条件**で区切り、条件を満たしたら [STATUS](../STATUS.md) の body track 節を更新する。段階内の順序は目安で、依存がないものは並行できる。

## B0: 設計（本文書群）

- 成果物: `docs/body/` の設計文書一式、[ADR 0002](../decisions/0002-body-track.md)。
- 完了条件: 依頼者が CONCEPT の忠実度の定義・非目標・未決事項の扱いを確認する。REQUIREMENTS の U 区分が依頼者の意図と一致する。
- 状態: 2026-10-10 起草。確認待ち。

## B1: 契約・骨格・形態 L1・書き出し

最初に動くもの。見た目より、再現性と形態の実測比較を優先する。

- `body-contracts`: 型、単位、座標系、コマンド・問い合わせ・イベントの骨子、キー付き乱数。
- `body-anatomy`: Rig-Core / Rig-Full の骨格テンプレート、関節種別・自由度、可動域表（出典付き）、体節慣性パラメータ、ANSUR II からの回帰係数（導出スクリプトを含む）。
- `body-morph`: `BodySpec` → 骨格寸法。体表メッシュは CC0 の基準メッシュを骨格に合わせてスケーリングする最小実装。
- `body-kinematics`: FK と可動域制約。IK は B2。
- `body-io`: `human-body/spec`・`skeleton`・`pose` の読み書き、glTF 2.0 書き出し（スキン付きメッシュ、A/T ポーズ）。
- `body-runtime`: 刻み、コマンド適用、チェックポイント、`human-body/run`。
- 検証: T0〜T2、形態の T4（ANSUR II の分割比較）を事前登録して実行。
- 表示: three.js の最小ビューア（CLI と同じランタイムを使う。親リポジトリの「CLI と UI は同じエンジン」の原則）。
- 完了条件: FR-MORPH-01/02/06、FR-KIN-01/02、FR-REC-01/02/03、NFR-01/03/04/05 の受け入れ条件を満たす。形態 L1 の T4 結果が記録される。glTF が公開検証ツールを通る。

## B2: 運動学 L1・運動制御 L1・リターゲット

- `body-kinematics`: IK（到達可能性の判定を含む）、姿勢プリセット、BVH / glTF からのリターゲットと接地補正。
- `body-motor`（L1）: 運動学ベースの歩行・走行・停止・方向転換・姿勢遷移。公開歩行データから歩幅・歩行率・関節角度の基準を取る。
- `body-face`: AU 正準、ARKit 変換、視線、瞬き。
- `body-dynamics` の後端選定: 自前簡易ソルバと既存エンジン（MuJoCo WASM、Rapier など）を同じ契約で動かして比較し、ADR に記録する。
- 検証: 運動（歩行）の T4 を事前登録して実行。
- 完了条件: FR-KIN-03/04/05、FR-MOTOR-01/02/05、FR-FACE-01/02/03 の受け入れ条件。歩行 T4 の結果が記録される。

## B3: 動力学 L2・把持・生理 L1・損傷 L1・エンジン連携

- `body-dynamics`: 選んだ後端で多体動力学、接触、ラグドール、バランス。慣性の T4。
- `body-motor`（L2）: トルク駆動の歩行・踏み出し。L1 との切り替え。
- `grasp`: 到達と単純形状の把持。
- `body-physio`（L1）: 代謝率と疲労の積算。ISO 8996 との比較。
- `body-damage`（L1）: 外部設定による損傷と機能低下、痛みの出力。
- アダプタ: Unity または Godot のどちらか一つを先に。BR-01 の「同じ関節角度列」を確認。
- 完了条件: FR-DYN-01〜05、FR-MOTOR-03、FR-PHYS-01/06、FR-DMG-05、BR-01、BR-04 の受け入れ条件。NFR-02 のベンチマークを公開（未達でも記録）。

## B4: 生理 L2・損傷 L2・形態 L2・橋渡し

- `body-physio`（L2）: 体温調節、心拍・呼吸、水分。
- `body-damage`（L2）: 接触力からの損傷判定、歩容への反映。
- `body-morph`（L2）: 体組成による体表変形、顔パラメータ。
- `body-bridge-hwl`: 親リポジトリの `Body` / `PhysicalEffect` との写像（任意）。親リポジトリの既定モデルは変えない。
- 完了条件: FR-PHYS-02/03/04、FR-DMG-01/02/03、FR-MORPH-03/04。

## B5: 公開準備

- 残りのアダプタ（Unreal、Blender、残るエンジン）、USD / FBX / VRM 書き出し。
- `FIDELITY.md` の整備、既知の限界の一覧、API リファレンス、チュートリアル。
- ライセンス表示、第三者資産の棚卸し、利用規約（[PRODUCT](PRODUCT.md)）。
- 別リポジトリへの切り出し（ADR 0002 の分割条件）。
- 完了条件: BR-02/03/05、NFR-06/07。外部の開発者が新規環境で B1〜B3 の検証を再現した記録が一件ある（親リポジトリの M4 と同じ考え方）。

## B6 以降: L3〜L4 と長期項目

- 筋モデル（Hill 型）、筋疲労、筋力の年齢・性差。
- 成長・加齢（子どもの資産を含めるかは別途判断）。
- 軟部組織の変形、皮膚。
- 睡眠・概日・栄養の長期収支。
- 慢性障害と回復の個人差。
- 多人数の同時実行とネットワーク同期（必要が生じたら）。

## 最初の一手（B0 の確認後）

1. `packages/body-contracts` を作り、単位・座標系・`BodySpec`・コマンド骨子を型にする。
2. `body-anatomy` の可動域表と体節慣性表を、出典列付きの JSON として起こす。
3. ANSUR II の取得・前処理・回帰導出スクリプトと、形態 T4 の protocol を `research/body/` に登録する。
4. 上記を使う T0〜T2 テストと `npm run test:body` を追加する。

## この計画が変わるとき

依頼者の確認で U 区分の要件が変わった場合、動力学後端の比較結果が想定と異なる場合、参照データのライセンスが利用を許さない場合に見直す。見直しの理由と変更点を ADR か [STATUS](../STATUS.md) に残す。
