# コンセプト: 操作可能な現実準拠の人間身体モデル

## 固定するコンセプト

**一つの正準な身体記述（解剖・寸法・物性・生理パラメータ）から、用途に応じた忠実度で、決定論的に動く身体を生成し、外部から操作できる。**

- 正準な身体記述は、特定のゲームエンジンや描画方式に依存しない。
- 同じ身体記述・同じ操作列・同じシードから、同じ結果が再現できる。
- 「操作」は、姿勢を取らせることから、力を加える、歩かせる、物をつかませる、表情を作る、疲れさせる、負傷させる、年を取らせるまでを、同じ命令体系で扱う。
- 忠実度は段階に分け、軽いゲームでは軽い段階を、研究用途では重い段階を選べる。段階が上がっても身体記述と操作APIは変わらない。

## 「限りなく現実に近い」の定義

印象ではなく、次の4軸について公開された計測値・規格との一致度で定義する。各軸に独立した忠実度レベルを与える。

| 軸 | 何が現実に近いか | 代表的な比較対象 |
| --- | --- | --- |
| 形態（Morphology） | 身長・体重・体節長・周径・体組成の分布と相互関係、骨格比率、顔・体表の形 | 人体計測データ（ANSUR II など）、ISO 7250 の計測定義、成長曲線（WHO/CDC） |
| 運動（Motion） | 関節の自由度と可動域、体節の質量・慣性、重心、歩行・到達・把持の運動学と動力学、バランス | 可動域の正常値表、体節慣性パラメータ（de Leva 1996、Dumas 2007）、公開歩行データセット |
| 生理（Physiology） | 代謝・体温調節・心拍呼吸・水分・疲労・睡眠の時間変化と運動との結びつき | ISO 8996（代謝率）、二節点体温調節モデル、筋疲労モデルの文献 |
| 応答（Response） | 衝撃・負荷・環境に対する損傷、痛み、機能低下、回復の時間経過 | 組織耐性の文献、損傷後の可動域・筋力低下の報告（**実測比較は後段**） |

形態・運動は公開データが多く、早い段階で実測比較ができる。生理は文献由来の係数で始め、応答は当面「工学的仮定」のまま明示する。軸ごとに現在の達成段階を [VALIDATION](VALIDATION.md) の規則で記録し、達成していない軸を製品説明で「現実準拠」と呼ばない。

## 忠実度レベル

各軸で L0〜L4 を定義する。製品の利用者は軸ごとに必要な段階を選ぶ。段階は積み上げで、上位は下位を含む。

| レベル | 形態 | 運動 | 生理 | 応答 |
| --- | --- | --- | --- | --- |
| L0 | 固定の基準体型。ヒューマノイド互換リグ | 運動学のみ（姿勢・補間）。可動域制約なし | なし | なし |
| L1 | 人体計測パラメータから骨格とメッシュを生成。5〜95パーセンタイルを覆う | 可動域・関節自由度が正常値表に従う。逆運動学。到達可能性の判定 | 運動量に応じた消費エネルギーと疲労の積算 | 可動域・筋力の低下を外部から設定できる |
| L2 | 体組成（脂肪・筋）による体表変形。顔パラメータ | 体節質量・慣性・重心が表に従う多体動力学。接触、転倒、バランス | 体温・心拍・呼吸・水分の粗い常微分方程式。環境との熱収支 | 衝撃から損傷の種類と部位を決め、機能低下へ写す。回復曲線 |
| L3 | 成長・加齢による形態変化 | 筋（Hill型）が関節トルクを出す。筋力の年齢・性差。筋疲労 | 疲労・水分・体温が運動性能へ戻る閉ループ | 損傷が姿勢・歩容・到達に反映。痛みの信号 |
| L4 | 軟部組織の変形（座る、押される）、皮膚のしわ・張り | 軟部組織の慣性と減衰、把持時の指先変形 | 睡眠・概日・栄養の長期収支 | 慢性的な障害、治癒の個人差 |

B1〜B3（[ROADMAP](ROADMAP.md)）では形態 L1〜L2、運動 L1〜L2 を目標にする。L3 以上は研究・医療訓練寄りの用途であり、ゲーム用途の既定ではない。

## 対象ユーザーと用途

| 利用者 | 典型的な用途 | 必要な段階の目安 |
| --- | --- | --- |
| ゲーム開発者（インディー〜中規模） | 体格の異なるキャラクターの生成、リアルな可動域の姿勢、ラグドール、負傷の表現 | 形態 L1、運動 L1〜L2、応答 L1〜L2 |
| シミュレーション研究者（人間工学・安全・訓練） | 到達・視界・姿勢負担の評価、転倒・衝突の再現、作業負荷と疲労 | 形態 L1〜L2、運動 L2〜L3、生理 L1〜L2 |
| アニメーション・映像制作 | 解剖学的に正しい基準ボディ、リターゲット先、表情の基礎 | 形態 L1〜L2、運動 L1 |
| AIエージェント・認知モデル研究（親リポジトリを含む） | 身体を持った個体に行動させ、身体感覚（疲労・痛み・温度）を知覚へ渡す | 運動 L2、生理 L1〜L2、応答 L1〜L2 |

## 製品の形

- **コア**: プラットフォーム非依存の数値カーネルと身体データ。初版は TypeScript で書き、親リポジトリと同じ実行基盤（Node、ブラウザ）で動かす。性能が必要な部分（多体動力学、衝突）は Rust → WebAssembly への移植を候補とし、入出力の契約を先に固定する。
- **資産**: 基準メッシュ、リグ、ブレンドシェイプ、テクスチャの最小セット。再配布可能なライセンスのもののみ。
- **アダプタ**: three.js、Unity、Unreal、Godot、Blender 向けの読み込み・同期層。コアの挙動はアダプタに依存しない。
- **形式**: 正準JSON形式と、glTF 2.0 / VRM 1.0 / USD / FBX / BVH への書き出し（[FORMATS](FORMATS.md)）。
- **検証スイート**: 忠実度の各軸を測る自動テストと参照データへの比較（[VALIDATION](VALIDATION.md)）。

詳細な配布形態とライセンスは [PRODUCT](PRODUCT.md) に記す。

## 認知の置き場所

身体コアは知覚・判断・学習の中身を持たない。しかし「身体に何をさせるか」を決める層がないと、ゲームや研究で使う人には不便である。そこで、**認知接続層（mind）**を製品の一部として定める（[ARCHITECTURE の「認知接続層」](ARCHITECTURE.md#認知接続層mind)）。

- 身体は毎刻み、本人の身体感覚（固有受容、接触、痛み、温冷、疲労感、渇き）を認知へ渡す。ホスト（ゲームエンジン・シミュレーション）は外界の知覚（見えるもの、聞こえるもの）を認知へ渡す。
- 認知は、身体へ与える命令（歩く、つかむ、表情、姿勢）を返す。認知の出力は通常の操作APIのコマンドであり、特別な裏口は作らない。
- 参照実装を製品に含める。簡易なスクリプト型（状態機械・行動木）と、親リポジトリの認知モデル human 0.2.0 を接続する実装の二つを予定する。利用者は自作の認知（ルール、強化学習、必要なら LLM）を同じ契約で差し込める。
- 認知の中身が決定論的でなくても、身体は受け取った命令をすべて記録するので、記録からの再現は保てる。非決定論的な認知を使った実行は記録にその旨を残す。
- 認知へ渡すのは本人の身体感覚だけで、他者の身体内部状態を渡さない（親リポジトリの情報境界と同じ）。

認知の妥当性（人間らしい判断か）は body track の忠実度の軸に含めない。それは親リポジトリの研究ループで扱う。

## 非目標

- 医療診断、治療計画、個別患者の予後予測への利用。生理・応答モデルは教育・娯楽・工学評価のための近似である。
- 実在の特定人物の再現、顔・体型による個人識別、スキャンデータからの本人特定。
- 性的コンテンツの生成を目的とした機能の開発。ただし、利用者がそのような用途に使うことを製品として制限はしない（依頼者の決定、2026-11-06）。法令の遵守は利用者の責任とする。
- 認知（知覚・判断・学習）の中身を身体コアに組み込むこと。認知は上記の接続層を通して外から差し込む。
- フォトリアルな描画そのもの（シェーダ、毛髪レンダリング）。描画はエンジン側に任せ、body track は形状・変形・パラメータを供給する。

## 親リポジトリのコンセプトとの整合

親リポジトリは「係数の由来を区別する」「面白さを妥当性の証拠にしない」「他者の内面を漏らさない」を重視している。body track では次のように引き継ぐ。

- 仕様・係数・資産に根拠区分（ユーザー要件 / 工学的仮定 / 文献由来 / 実測比較済み）を付ける。
- 「人間らしく見える」は受け入れ条件にしない。受け入れ条件は計測値との差、制約違反の有無、再現性で書く。
- 身体の内部状態（痛み、疲労など）を外部へ渡すかどうかは利用側が決める。認知モデルに接続する場合は、本人の身体感覚だけを渡し、他者の身体内部状態を直接渡さない。

## 依頼者が決めた事項（2026-11-06）

B0 の確認で依頼者が決めたもの。根拠区分は U。

1. 忠実度の4軸とレベル、対象ユーザー、製品の形は概ねこのままでよい。
2. 認知を処理できる場所を設ける。上記「認知の置き場所」として設計に入れた。
3. 性的コンテンツは目的ではないが、製品として制限しない。
4. 初版の配布資産は成人のみ。成長モデル（子どもの体格）はデータとしては設計に残すが、資産の配布は後段で別に判断する。

## 未決事項

実装前に決める必要があるが、この版では決めていないもの。決めたら [REQUIREMENTS](REQUIREMENTS.md) か ADR へ移す。

1. 多体動力学の実装方針: 自前の簡易ソルバで始めるか、MuJoCo / Rapier などの既存エンジンを最初から後端に使うか。契約を先に固定し、B2 で判断する。
2. 顔の正準表現: FACS のアクションユニットを正準にし ARKit 52 形状へ写すか、逆にするか。
3. 筋モデルを含める範囲: 全身 80〜90 筋腱単位の既存研究モデルに倣うか、関節トルクで近似する段階（L2）を長く使うか。
4. 軟部組織の変形方式: 補正ブレンドシェイプで止めるか、位置ベース動力学へ進むか。
5. 商用利用者に対するサポートと保証の範囲。
6. 参照実装の認知（スクリプト型）にどこまでの行動の語彙（追う、避ける、拾う、待つなど）を持たせるか。
