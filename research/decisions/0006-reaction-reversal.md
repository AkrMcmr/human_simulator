# 0006 / 相手の反応の途中変化に対する更新の遅れと、接触のない期間の忘却

- 状態: 登録。protocol・研究コード・閾値をコミットしてから開発・確認シードを実行する。
- 対象モデルとソース: 既定human 0.2.0。相手が動かない制御課題なので予測効用は0になり、0.1.0と同じ値になる（テストで確認）。既定モデルの現象確認で、候補比較ではない。ただしこの評価器は次の忘却則の候補比較にも使う。
- 根拠: 工学的仮説。[判断0005](0005-experience-history-m2.md)の次の問い「相手の反応が途中で変わる条件」と「忘却が事前分布へ戻る仮定の見直し」に対応する。[中期目標M2](../../docs/MIDTERM_GOALS.md)の「相手の反応の途中変化を比較する」「警戒の固定化や更新の遅れを評価する」に従う。
- 仮説と反証条件:
  - R1（無害→危害の更新の遅れ、capability）: 無害履歴60ステップの後に危害が始まると、履歴なしより30ステップ後の危険度が低い（証拠の蓄積が更新を遅らせる）。差が0.05未満なら反証。
  - R2（遅れは履歴長で増える、property）: 無害履歴240は60よりさらに低い。差0.02未満なら反証。
  - R3（危害→無害の回復、capability）: 危害履歴60の後に無害が30ステップ続くと危険度が0.10以上下がる。
  - R4（回復も履歴長で遅れる、property）: 危害履歴240は60より30ステップ後の危険度が0.02以上高い。
  - R5（接触のない期間の忘却、property、好ましい向きはlower）: 無害60ステップの後、相手が8uで見えるだけの期間が480ステップ続くと、証拠が事前分布へ戻って危険度が0.02以上上がる。これは現行の忘却則の記述で、次の候補が変えることを目標にする性質。
- 変更するもの・追加する仮定: 人間モデルの計算は変えない。研究コード`research/studies/reversal-v1.ts`と`npm run study:reversal`（`--model`と`--baseline-model`で対比較も可能）を追加。提示は1ステップにつき知覚→痛み→知覚で近接証拠を1件更新する。
- 固定するprotocolと評価器: [`research/protocols/reversal-v1.json`](../protocols/reversal-v1.json)。
- 閾値の決め方: パイロットシード8101–8104で尺度を確認（R1約0.24、R2約0.09、R3約0.16、R4約0.08、R5 0.07）してから固定。パイロットはゲートに使わない。
- 開発条件・未使用の確認条件: 開発8001–8008、確認9001–9008。いずれも未使用。
- 本人に渡さないもの: ブロックの切り替え、条件名、安全/危険のラベル。
- 判定: 全達成ならR1〜R5を既定モデルの性質として記録し、R5を改善目標とする忘却則の候補を`prospective`で登録する。未達は反証として残す。
